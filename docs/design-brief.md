# 设计说明

## 定位

“17号的航行日志”是 ElysiaFollower 的个人博客，也是一套强主见的 Astro
主题。它首先服务于作者本人的研究、写作与创作习惯；其他人可以复制源码，
但通用性不反过来约束站点的构图与气质。

设计需要同时容纳两种状态：

1. 首页、About、相册与友链负责建立印象，可以使用角色美术、昼夜场景、
   非对称构图与经过编排的动效。
2. 文章、知识目录与阅读页负责长期使用，需要安静、清楚、响应迅速。

两类页面共享色彩、字体与图形语言，但不强迫所有页面采用同一种版式。

## 视觉原则

- 大图负责情绪，界面负责秩序。装饰不能妨碍导航和阅读。
- 重要页面应有清楚的起承转合，而不是堆叠同一种卡片。
- 文章正文保持稳定行宽；目录、批注和舞台按内容需要进退。
- 日间与夜间不是简单反色，而是两套协调的观看环境。
- 动效用于提示层级和转换节奏，不用持续缩放或无意义运动制造热闹。
- 桌面端承担完整构图；窄屏可以简化，但不能溢出、遮挡或失去核心功能。

## 页面职责

### 首页

首页建立站点气质，并提供文章、相册和 About 的入口。近期文章只承担预览，
完整的时间浏览属于文章页，个人履历属于 About。

### 文章

`/posts/` 是发现页。它保留封面和时间线，让读者从新到旧浏览全部公开文章。

`/posts/catalog/` 是检索页。目录映射本地文件树，Tags 表示跨目录关系，
Pagefind 提供全文搜索；排序只改变当前视图，不增加作者维护成本。

### 阅读

正文优先。桌面端目录和旁注只在有空间时出现；`Stage` 可以暂时收起边栏，
让图示、视频或交互解释器获得完整宽度。舞台内部不使用边栏旁注。

### About

About 单独承担身份、研究方向、兴趣与联系入口。它可以比首页更直接地说“我”，
也允许少量俏皮表达，但事实信息必须准确。

### 相册

相册用于观看，而不是管理。瀑布流负责浏览，PhotoSwipe 负责拿起一张图之后的
缩放、拖拽、切换与键盘操作；图片按接近视口的顺序加载。

### 友链

友链展示作者长期阅读的个人站点。条目数量增加时仍保持线性、可扫描的结构，
不使用层层嵌套的卡片。

## 内容模型

文章目录同时决定本地位置、网站目录和 URL：

```text
src/content/posts/<类型>/<领域...>/<文章>/index.mdx
```

固定类型为 `notes`、`papers`、`engineering`、`problems`、`reflections`
和 `projects`。更深层的知识结构由目录自由表达；Tags 只承担交叉关系。

所有文章统一使用 MDX。普通文章直接写 Markdown，需要时再插入集中注册的
旁注、图示、视频、舞台或交互组件。

## 配置边界

适合配置：

- 站点名称、导航、引语和外部链接
- About 资料、友链、相册条目
- 文章元数据、封面焦点与 Tags
- 内容目录的固定根节点

由主题决定：

- 页面构图与信息层级
- 字体关系、色彩和动效节奏
- 组件的视觉结构
- 构成站点身份的独特交互

当配置会破坏整体协调性时，保留主题自身的判断。

## 发布能力

生产构建默认生成 canonical、Open Graph、Twitter Card、文章 JSON-LD、RSS、
sitemap、Pagefind 索引和旧 URL 重定向页。GitHub Actions 在部署前执行
类型检查、生产构建与产物验证，仓库不保存 `dist/`。

迁移到用户名站点的操作见 [`migration.md`](migration.md)。
