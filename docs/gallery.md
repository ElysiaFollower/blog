# 相册维护

相册用于欣赏、浏览和分享收藏。作者在 2026-10-29 明确：审美体验优先；性能主要通过懒加载、分段展示、离屏资源管理改善，不自行以压缩画质或把动态内容改成静态图作交换。原图直接用于浏览是有效选择。

同一份收藏计划提供浏览与展览两种观看方式。当前实现默认浏览，展览尚未实现；美术参考中的场景仍是候选。

作者在 2026-10-30 补充：图片必须完整展示，不裁剪，支持不同尺寸与比例；可在保持比例的前提下适度缩放，可有适度变化的图片间距，也可接受不过分的留白。不要为了填满版面牺牲作品。具体缩放与间距数值尚未被用户规定，属于需要结合屏幕与实际作品调整的排版选择。

## 代码边界

- `src/lib/gallery.ts`：构建期归一化来源，验证尺寸与唯一 ID；输出 `src/types/gallery.ts` 中可序列化的 `GalleryEntry`。
- `src/components/gallery/layout.ts`：无 DOM 的布局计算，保留比例。横幅通常占两个基础列，其他占一列；窄屏在两列高度差较大时缩为单列横幅，避免整行跨列制造大空洞。这些是可调整的设计选择，不是用户永久规格。追加不改变既有位置。
- `GalleryBrowse.astro` / `gallery.css`：浏览页面内容与样式，初始输出 24 项；容器单位让预计算坐标随宽度缩放，三个断点对应 2/4/6 个基础列。
- `browse.ts`：分段追加、视口附近加载/远处释放、视频播放状态、作品 URL 与返回；只在打开作品时加载查看器模块。
- `video-playback.ts`：区分用户播放意图与环境暂停，保留远处卸载前的进度；可独立验证异步媒体事件。
- `viewer.ts` / `GalleryLightbox.astro`：PhotoSwipe 交互与样式；依赖完整数据，独立于已挂载多少卡片。支持原图/原片、信息、复制作品链接和键盘操作。
- `src/pages/gallery/index.astro`：只负责页面装配与页头。

未来展览可消费同一份数据与作品 ID，自行管理场景和资源；不依赖浏览布局的 DOM，也无需为它预建插件框架。

## 添加内容

本地图片仍放在 `src/config/gallery.ts`；远端/公开目录图片仍在 `src/config/r2-gallery.json`。宽高必须是准确的正整数。图片 ID 来源于原始路径/URL 的哈希，重排不会改变 ID，换源会改变 ID。

视频放在 `src/config/gallery-videos.ts`，提供稳定 `id`、`src`、`poster`、`width`、`height` 和可选文字；海报不是视频的替代品。默认浏览在可见时静音循环播放，保留原生控制条和放大入口；离屏或打开查看器时暂停。用户手动暂停会被保留，远处卸载后尝试恢复播放进度。浏览器拒绝自动播放或用户要求减少动态效果时，原生控件仍可播放。当前真实收藏暂无视频，不能把类型检查等同于真实视频播放验收。

图片不重新编码，GIF 在浏览中使用动画原图。离开预加载范围后释放媒体源，再接近时恢复；GIF 可能从头开始。当前实现以分段 DOM 与离屏资源管理控制开销，没有宣称任意数量收藏的常量内存或稳定帧率。

## 验证

- `node scripts/test-gallery-layout.mjs`：真实行为不变量（比例、边界、无重叠、追加稳定）。Node 22.18+ 或 Node 24 可直接运行 TypeScript 测试依赖。
- `node scripts/test-gallery-playback.mjs`：模拟异步媒体事件，验证手动意图、环境暂停、减少动态效果、自动播放拒绝、进度恢复；不替代浏览器媒体验证。
- `pnpm verify`：类型、生产构建和发布产物。
- 浏览器：连续与反向滚动、原图/GIF、打开/切换/缩放/关闭、浏览器返回与直接访问作品链接、复制反馈、昼夜、窄屏和失败入口。

`docs/issues.md` 原文及旧技术文章描述的是历史问题/实现。需要判断当前行为时，以本文件、代码和本轮验证为准。
