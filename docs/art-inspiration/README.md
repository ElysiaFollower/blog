# 美术探索与设计参考

本站希望持续进行以技术美术为主的艺术探索。这里收集值得研究的作品，提炼可复现的设计语言，并讨论它们适合如何进入博客。应用范围可以是全站、一个页面、一个局部，也可以是独立的艺术展示页，由作品形式和页面职责决定。

这里的目标是帮助设计者作判断，而不是把“高级感”变成一张特效清单。可以大胆探索；收敛时再比较视觉收益、制作成本与运行负载。

开始实际任务时，先读本页和 [站点设计说明](../design-brief.md)，再按任务读对应文档；不要求每次重新遍历所有参考网站。

本目录保存理解设计所需的审美背景、参考入口、判断与候选方案，不依赖原始聊天记录或会话附件。工程规范和现有代码通过仓库相对链接查阅；用户只需说明本次要处理的页面与目标，无需重新提供参考网站或转述偏好。

原站、案例和截图入口集中在 [references.md](references.md)。视觉资料目前主要是外部链接，并非离线素材归档；网站可能改版，截图不能代替交互体验。需要复核时按条目查原站和案例，访问失败时说明缺失证据，不凭文档推断原站的当前实现。

## 已确认的审美倾向

以下来自 2026-10-28 至 2026-10-29 的讨论，属于作者偏好，不是对网站性能的测量结论。

- 希望网站有强导演感、大气、灵动，允许惊艳、酷和明确的艺术表达。
- 对 **Unseen** 的入场切换、拖拽卡片及整体设计感印象尤其深。
- 对 **Samsy** 赛博城市的色彩、光影和空间表现印象尤其深；这不等于已选择赛博朋克作为全站风格。
- 喜欢 **Immersive Garden** 的艺术风格，喜欢 **Lusion / Lando Norris** 用编排增强普通页面滚动的方式。
- 喜欢 **Dennis Snellenberg** 的动效，同时在访问时感到卡顿；原因尚未定位。
- 风格调研先充分探索，记录成本，最后再作取舍；不能因为担心性能就预先把方案全部收缩成轻微淡入。
- 最终作品仍需要好用、流畅。审美表达与使用体验都属于质量，不用“这是艺术”掩盖输入延迟、长时间等待或阅读困难。

## 文档之间的关系

- [design-brief.md](../design-brief.md) 管站点定位、页面职责与长期设计边界。
- 本目录管美术语言、参考依据和候选应用方向。`page-directions.md` 区分作者已表达的方向与 Agent 的**提案**；执行范围以本次任务为准。
- [voice.md](../voice.md) 管公开文案；[interactive-articles.md](../interactive-articles.md) 管文章交互与内容组件契约。
- [issues.md](../issues.md) 中的现有问题需要回到代码核实；不能把尚未完成的功能当作设计基础。

已确认的偏好、设计者的建议、当前实现事实应分别说明。新的明确用户决定优先于旧提案；一旦方向被采用，更新相关段落，不要保留两套互相矛盾的“最终方案”。

## 给执行 Agent

根据这些材料形成自己的设计判断。先实际查看目标页面及主要交互，识别应保留的优点和具体问题，不能仅凭代码判定美术效果。改动前保存必要的原版截图或交互记录，供新旧比较。说明这次的视觉目标、改动范围与主要参考手法；用分镜或局部原型让用户能看到提案，避免仅用“高级、丝滑、沉浸”描述效果。

用户负责表达审美和判断体验，不需要替你选择动画库、反射算法或组件结构。只有会改变整体气质、扩大范围或引入重大资产/架构成本的分歧，才需要集中对齐。不要把本目录变成每一步都要审批的流程。

参考网站按需单独打开，看完及时关闭。重渲染站不同时常驻；优先复用已有案例、截图和作者说明。参考作品的视觉与源码可用于研究，收录链接不意味着可以将其图片、模型、字体或代码直接用于本站。

## 如何维护

新增参考时写清它带来了什么新认识；相同手法优先补充现有条目。实际原型得到的新结论回写对应设计模式或页面提案，不另建一份逐日流水账。这里只保存有助于下一次设计的证据、判断与应用建议。
