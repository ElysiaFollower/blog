# 页面应用方向与下一步

本页基于 2026-10-29 源码检查、审美讨论，以及相册桌面日间首屏与向下浏览画面的观察，**不是已批准的全站改版计划**。未完成相册交互、移动端或性能测试；其他页面尚未做本轮视觉复核。执行前重新核对目标页面，不能将路径清单当作永久架构描述。

## 当前探索重点：相册的多种观看体验

**作者已表达的方向：** 先逐页改进，当前优先关注相册；它已有艺术基础，也有需要处理的功能问题。作者提出并认可同一份收藏提供多种观看体验：默认使用便于连续浏览的瀑布流，通过按钮选择更具艺术表现力的展览。该方向尚未实现，具体任务需分别说明功能修复与美术探索的范围。

**当前画面观察：** 首屏以大号衬线“画廊”、较多留白、细分隔线和粉色点缀建立画册感；下方是四列图片，页面标注 173 项收藏。竖幅在视觉上占据较大面积，横幅较小；精细插画、角色图和趣味表情图混合陈列。美术判断是可加强作品之间的主次与情绪衔接，而非直接推翻既有气质。数量和布局仅描述观察时的状态。

以下是 Agent 提出的候选形式，尚未由作者选定具体构图：

| 形式 | 美术语言与观看体验 | 适合的位置 |
| --- | --- | --- |
| 私人画集 | 横竖幅获得合适的展示份量，少量重点大图、成组作品与留白形成节奏；色彩、主题或情绪建立相邻关系 | 默认浏览模式的美术候选；分组与重点编排需考虑持续新增作品的维护成本，不要求全库手工排版 |
| 暗室光箱 | 深色环境中突出作品的光色，选中画面靠近或展开，其余环境退暗；氛围围绕作品建立，保留原图颜色 | 夜间气质、大图观看或展览环境的候选 |
| 空间收藏墙 | 作品错落排列，有前后层次、拖动反馈、惯性与选中后的聚焦转换 | 沉浸展览的候选，可先以精选作品验证；不意味着默认浏览也要空间化 |
| 城市场景 | 收藏与街区、橱窗、灯箱或投影产生内容关系，让空间参与组织作品 | 更完整的艺术探索方向；不能仅因喜欢 Samsy 就认定必须建城市或多人世界 |

[Unseen](references.md#unseen-studio入场与空间画廊) 主要提供入场、空间陈列与拖拽手感的参考；[Samsy](references.md#samsy-ninja城市的光色与空间可信度) 主要提供色彩、光影与空间可信度的参考。两者可以组合为一个展览，也可以发展成不同体验；不是已经决定必须制作两套仿站。

**设计建议：** 先考虑“浏览 / 展览”两种完整体验，具体名称和场景继续探索。默认浏览本身应有完成度；沉浸体验由用户主动进入，退出后能回到原来的作品与浏览上下文。展览未启用时不应拖累默认模式。两种观看方式共享收藏来源；若展览只展示精选，应明确其范围，不让用户误以为其余作品丢失。模式切换、数据关系和资源生命周期是后续设计与实现需要解决的问题，目前没有现成实现或性能结论。

## 现有基础与合适的应用位置

| 页面/范围 | 当前基础 | 候选设计 | 应保留的职责 |
| --- | --- | --- | --- |
| 首页首屏 | 昼夜主图、遮罩、HTML 标题、文章入口 | 重新组织光色与视点；将开场结束接到主视觉进入；需要时加入局部视差或有限镜头变化 | 建立站点身份，并能直接进入内容；不能要求每次访问都观看完整演出 |
| 首页“记忆的回廊” | 独立区域、角色肖像、文字、画廊入口 | 少量精选作品的空间陈列、拖动惯性、选中作品后的连贯转场 | 展示精选并引导进入完整画廊，不替代大规模图片浏览 |
| About | 角色首屏、研究方向、兴趣、联系入口 | 角色/文字前后景、研究到兴趣的章节转换、动态排版 | 真实身份资料与联系方式可以快速读到；不随美术改版编造履历或研究事实 |
| Gallery | 全量图片节点、近视口请求、CSS columns、PhotoSwipe | 默认瀑布流浏览与可切换的沉浸展览；具体形式见上文 | 保留连续浏览、缩放、键盘、触控、原图直链与加载能力；模式间保持可理解的作品与返回关系 |
| 文章发现页 `/posts/` | 年份与时间顺序、封面、摘要、Tags | 动态编辑式版面、年度章节感、封面与标题的短促响应 | 按时间发现全部文章，避免变成只展示少量“主打作品”的展厅 |
| 目录 `/posts/catalog/` | 文件树、Tags、Pagefind、排序、URL 查询状态、分批结果 | 清楚的选中态、面板转换和结果变化反馈 | 检索及时、状态清楚；不为演出延迟输入或结果，不重定义目录语义 |
| 文章阅读与 `Stage` | 稳定行宽、目录/旁注、跨栏舞台、MDX 组件 | 在内容需要处放入音频、图形或算法实验；关键章节可暂时展开 | 普通正文安静可读，舞台内媒体展开而文字仍易读，保持锚点与索引 |
| 友链 | 大字引入、线性条目、头像、描述和外链 | 行级反馈、头像的局部响应、克制的进入节奏 | 条目增加后仍可扫描；不把全部站点藏进需要漫游寻找的空间 |
| 独立艺术页（尚未创建） | 可沿用静态页面与 `BaseLayout` | 自成作品的光影场景、声音互动或空间实验 | 有独立表达价值时保留；临时预览路由不应无意演变成第二套首页 |

### 实现接点

- 首页主体：[HomeExperience.astro](../../src/components/home/HomeExperience.astro)。当前依次为主视觉、近期文章、频道入口、记忆回廊；路由 [index.astro](../../src/pages/index.astro) 只挂载该组件。
- 入场：[OpeningSequence.astro](../../src/components/OpeningSequence.astro)。当前是等待字体和当前主题图片、会话内只出现一次的淡出门帘，不是连续镜头演出。装饰进度条不代表真实下载进度。
- 出现动画：[ScrollReveal.astro](../../src/components/ScrollReveal.astro)。当前是进入视口触发一次，不是连续滚动时间轴。局部滚动编排不应直接把它扩成全站场景系统。
- 指针：[DirectedPointer.astro](../../src/components/DirectedPointer.astro)。当前有跟随圆环、悬停扩圈与点击反馈，没有磁吸或拖拽惯性。场景专属行为留在场景组件内。

- 阅读：[ReadingLayout.astro](../../src/layouts/ReadingLayout.astro)、[Stage.astro](../../src/components/content/Stage.astro)、[reading.css](../../src/styles/reading.css)。沿用 [文章组件约定](../interactive-articles.md)。

### 相册的已知问题

[issues.md](../issues.md) 描述的增量瀑布流问题，当前仍由代码印证：模板一次输出所有图片节点；IntersectionObserver 只在接近视口时发起图片请求；布局仍使用 CSS columns。

因此不能把它写成“已完成 DOM 分批追加”。若选择完整相册改版，应把批次追加、顺序与比例问题明确纳入范围；若只做首页精选回廊，则保留这个独立问题，不顺手把图库重构带进局部美术实验。

## 可选应用：一段可以接回首页的精选回廊

**为什么选它：** 它已有观看和进入图库的语义，又能同时检验作者最喜欢的入场切换、空间陈列、拖拽与光色。相比把首页所有板块同时改造，局部作品更容易形成完整体验，也更容易看清哪种手法真的有效。

这是独立的候选应用，不是相册任务的前置条件。作者当前选择先关注相册，不能因本节较具体就转去改首页。About 首屏、首页主视觉和文章 Stage 同样是其他范围的候选，不因某个方向更易实现就将其提升为作者最偏好的艺术方向。

### 初始设计命题

> 把首页的静态“记忆的回廊”发展成可以进入、拨动、停留的精选展示；选中作品后，视线自然进入图片或完整图库。

优先使用真实站点作品和现有文案。空间陈列不要求做一整座城市。主题名称“回廊”也不要求把场景做成字面上的建筑走廊；根据素材选择合适构图。

### 两种可以比较的气质

- **柔光方向：** 保留清楚轮廓、轻微景深层次和安静的环境，重点比较空间与文字的关系。
- **夜景方向：** 用深色环境、少量发光面和反射延伸色彩，重点比较光色与作品本身是否协调。

若两种方向确实有分歧，使用相同作品、相同核心操作作关键静帧或短样片比较。无需预先完整实现两套站点；更不必把两个方向所有特效同时叠加。

### 可供设计者调整的初始分镜

| 状态 | 用户看到什么 | 用户仍能做什么 |
| --- | --- | --- |
| 接近章节 | 当前作品或场景轮廓先建立焦点，文字提供入口上下文 | 正常滚动、继续浏览或跳过 |
| 进入 | 一个明确的视点或视觉锚点完成从普通页面到展示范围的变化 | 保留可预测的滚动/返回关系 |
| 浏览 | 少量精选作品具有前后层次；输入直接响应，松手后的运动有收束 | 拖动、选择；触屏和键盘具有等价核心路径 |
| 打开或离开 | 选中作品接续到图片观看，或通过明确链接进入完整图库 | 返回原浏览状态，继续进入博客其他内容 |

只在需要的关系上使用滚动、拖动和点击，避免一个手势同时改变镜头、选择作品和跳转页面。环境运动属于可选项，不是完成这段体验的必要条件。

### 原型的工程边界

设计与实现共同决定是否需要真实透视变化、遮挡、材质响应或连续形变，再选 DOM、2.5D、视频或实时 3D。不要预设必须用 WebGL，也不要预设必须做成平面低配版。

可先用独立组件承载，在临时预览路由检查，再接回首页；也可以直接在隔离的开发改动中调整原局部。临时路由不加入正式导航，合入正式页面时清理预览包装。若需要保留在构建输出中，使用 `BaseLayout` 的 `noIndex` 并单独处理 sitemap 排除；当前 `noIndex` 不会自动修改 sitemap，也不阻止直接访问。正式决定保留独立艺术页时，再明确其内容与入口。

原型应保留此次要验证的核心视觉与输入关系。若因资产缺失或技术简化而改用占位图、固定视频或假交互，应明确缺失部分，不能把结果称为已验证完整方案。模型、分层素材、音频或字体缺失时，先列出制作方案与来源，再决定投入；不要以大量临时素材掩盖设计尚未成立。

## 怎样组织下一轮工作

不必先列出全站每个页面怎么改，也不必先建立一群各自设计页面的 Agent。先由一个主执行 Agent 负责同一段体验从构图到实现的一致性；可让辅助 Agent 检查来源、代码边界或性能，但不把同一页面的审美拆成互不交流的任务。

一个足够小而完整的推进过程是：

1. **具体化提案。** 执行 Agent 先实际查看本次目标页面，留下必要的原版画面与交互对照，再说明保留项、要改善的问题、目标感觉、关键状态、资产需求和主要成本。用户只需判断气质是否对，不需要选择技术细节。
2. **做可操作的局部初稿。** 先完成进入、停留、操作、退出的完整关系；用少量真实内容，使视觉和使用都能被评价。已有授权范围内的常规实现自行推进。
3. **集中审阅实际体验。** 静帧看构图，实际运行或短录屏看节奏与手感；同时说明在哪些设备测过、哪些还没有。把问题集中为“哪里吸引人、哪里拖沓、哪里操作不舒服”，不要把用户变成逐条验收动画参数的人。
4. **采用后整合。** 确认局部值得保留，再接入目标页，并提取实际重复的视觉/运动规则。清理被替代的临时方案；有价值的新判断回写本文或设计语言。不要在一个原型前就建设全站通用动效框架。

阶段是否暂停取决于用户对下一轮的授权，不是每步都必须重新确认。纯粹的视觉探索也可以自主完成可比较初稿，再集中请用户判断。全站气质改变、重要功能让位或新增重大资产/后端投入时，应明确提出差异。

### 开发任务中如何引用本目录

用户说明目标页面和任务范围后，可附上以下说明。它提供设计上下文，不额外扩大任务；只要求评审时，不应直接开始实现。

```text
美术设计请从 docs/art-inspiration/README.md 开始，按任务查阅目录内的设计语言、
参考网站、成本和页面方向；相关站点规范与源码入口已有链接，不需要我重述聊天背景。
区分已表达的偏好、候选提案与当前实现。先实际查看目标页，保留原有优点，
在本次授权范围内形成具体设计并推进，不因参考丰富而扩大为全站改版。
参考站按需单独打开，看完关闭；交付时说明实际验证结果和仍缺失的证据。
```

可以在本对话继续，也可以把这段任务交给新的仓库对话。新对话的意义是范围清楚、上下文干净；设计依据已经在仓库，不需要用户重新讲一遍审美。
