# 可复现的美术语言

本页是设计参考，不是要求每个页面同时实现全部效果。原则允许具体作品作有意识的例外；例外要能解释视觉目的，而不是机械追求与参考站相似。

## 把风格、手法与技术分开

“柔光超现实展厅”是一种风格；“视点穿过入口，内容接续显露”是一种手法；“Three.js 相机轨道”只是实现路径。先明确前两者，再根据需要选择技术。同样的手法可以用平面、2.5D、视频或实时 3D 表达，它们的能力并不完全等价。

当前值得保留的艺术方向如下，均为候选，尚未选定全站风格：

| 艺术方向 | 画面语言 | 与本站结合时的判断 |
| --- | --- | --- |
| 柔光超现实空间 | 简洁建筑、柔和明暗、低对比环境中的明确焦点、水面或少量反光材质 | 从 Unseen 学空间和进入感；与本站角色美术、日间环境如何协调，需要看具体构图 |
| 夜景中的发光空间 | 深色环境、局部亮色、发光面、反射与远近层次 | 从 Samsy 学光色关系；可以只保留一个场景，不必接受城市漫游、游戏 UI 或多人功能 |
| 雕塑与展览式构图 | 材质、轮廓、负空间、少量大尺度图形与克制文字 | 从 Immersive Garden 学艺术气场；适合专题与个人展示，不必把整个博客改成灰色作品集 |
| 动态编辑式页面 | 明确的字号差、非对称布局、内容分章、图文的先后进入 | 从 Lusion、Lando、Dennis 学节奏；适合把现有页面组织得更有表现力 |

本站既有的角色、插画、昼夜两套环境和中文内容需要进入构图。不要用参考站的商业品牌、赛车符号或英文大字替换掉本站身份，只因那样更容易做得像。

## 共同的设计判断

- **静帧先有构图，运动再扩展构图。** 任意停在一个关键状态，主体、内容和留白应仍有关系；不要靠持续运动遮掩画面空洞。
- **用主次组织注意力。** 光、字号、尺度、运动与交互都能建立焦点，通常不需要让它们同时争夺视线。主次不是固定颜色数量或固定组件数量。
- **给变化一个空间或叙事理由。** 内容靠近、被揭开、被拿起、进入另一个空间，比所有元素各自随机飞入更容易建立整体感。
- **艺术表达本身也是有效目的。** 环境运动可以只为情绪和世界观服务，不必全部解释成功能反馈；同时要知道它在什么时候应退居背景。
- **整站共享语言，不共享所有强度。** 字体关系、材质线索与运动节奏可以连续，首页、目录、文章正文不必具有相同的运动密度。
- **中文排版是构图的一部分。** 使用真实标题、段落长度和窄屏断行检验设计；英文作品集的字宽与留白比例不能原样套用。

## 模式一：用光色与材质建立空间

**希望产生的感觉：** 画面有深度、材质可信、光线有方向，用户愿意多看一眼。写实不是唯一目标；风格化也可以拥有可信的空间线索。

设计时先决定主体和视点，再安排环境明暗、主光、强调色与反射。通过前后遮挡、尺度、远处对比度下降建立层次。材质对光线的不同回应，比所有表面一起发亮更有说服力。

可以复现为一张精心制作的场景图、一段固定镜头视频、分层视差，或可改变视角的实时场景。3D 的独特价值在于视角变化下仍保持一致的透视、遮挡与对象关系。固定视角的预渲染画面不能无损替代自由观察。

**失去质感的征兆：** 满屏同样明亮、每处都发光、辉光掩盖轮廓、材质缺少差别、3D 很复杂但构图没有主体。bloom 是亮部扩散的后处理，不等于完成了场景布光。

参考：[Samsy / Unseen / Immersive Garden](references.md)。实现分档见 [implementation.md](implementation.md)。

## 模式二：剪辑式转场

**希望产生的感觉：** 页面变化是一次经过设计的事件，用户知道视线应该跟随什么。

先指定离开状态、到达状态和两者之间的视觉联系，再选择转场方法：

- **遮挡：** 前景物体或色块覆盖视野，在遮挡时更换内容，再揭开。
- **匹配：** 卡片主图扩展为下一页主视觉，让同一个对象贯穿变化。
- **穿越：** 视点靠近窗口或画面内部，进入另一层内容。
- **切换与停顿：** 明确切到新构图，再让它稳定成立；并非所有动作都要连续柔滑。

抽象分镜是“建立焦点 → 发起动作 → 状态转换 → 新内容落位”。用户触发后，这段过程主要由时间控制。转场要能处理用户返回、重复点击、资源未就绪等真实状态，不只演示理想的一次播放。

**失去质感的征兆：** 每次导航都强制看同一段长演出；画面变化很忙但焦点丢失；加载尚未完成却伪装成已经到达；转场结束后仍不能操作。

可用普通页面的遮罩、位移与状态过渡，也可使用空间相机轨道。Unseen 是体验参考，不能据此断言其原站采用了某种具体算法。

## 模式三：滚动驱动的章节编排

**希望产生的感觉：** 用户通过滚动推进一段视觉过程，章节之间有铺垫、变化和停留。

区分两种控制：滚到某处后自行播放是“滚动触发”；滚动位置直接决定画面状态是“滚动绑定”。后者可以概括为 `画面状态 = F(章节进度)`，输入来自页面滚动，不依赖鼠标设备本身。

先画出关键状态，再决定它们占据多少滚动距离。例如：完整场景 → 靠近主体 → 主体局部占据画面 → 局部成为下一章背景 → 内容进入。给需要阅读的状态足够停留空间；反向滚动时关系也要成立。

舞台可以暂时固定，文字、图片或相机在其中变化。不要默认把原生滚动替换成另一套平滑滚动系统；进度编排与滚动手感是两个独立选择。

**失去质感的征兆：** 所有元素同速平移；为了看一段文字需要滚很多屏；用户刚读到内容它就消失；只有向前滚动的演示成立。

参考 Lusion / Lando；博客中的应用范围应由章节内容决定，不能全站统一添加长距离固定舞台。

## 模式四：可直接操纵的空间画廊

**希望产生的感觉：** 用户正在拨动或拿取内容，内容具有重量、深度和稳定的落点。

将交互拆成可独立设计的关系：

- 拖动距离决定内容位置；输入首先要及时响应。
- 拖动速度可以影响有限的倾斜、拉伸或弯曲。
- 松手后保留惯性，再逐渐衰减；需要时加入边界阻力或落点吸附。
- 点击选中的作品后，可以让它扩展为详情的视觉锚点。

并非每个画廊都需要所有关系。普通位移、旋转和透视可以由 DOM / CSS 3D 实现；只有连续弯曲或特殊材质效果才需要考虑网格与 shader。大量作品的检索，与少量精选作品的空间展示，是不同任务。

**失去质感的征兆：** 松手后的惯性变成拖动中的输入延迟；拖拽经常误触点击；所有信息都藏在不可发现的空间角落；触屏只能靠猜手势。

Unseen 的拖拽体验是主要参考；这里的机制是可选复现方法，不是原站源码说明。

## 模式五：局部感知与反馈

**希望产生的感觉：** 场景注意到了用户，对象与操作之间存在连续的因果关系。

可按 `输入位置 / 速度 → 影响范围 → 响应强度 → 恢复方式` 设计。按钮轻微吸附、文字字形变化、图像局部扰动、物体避让都属于这一类。

先定义对象材质与动作是否相符，再决定影响半径、幅度和恢复速度。近处强、远处弱，或不同层次具有不同响应，通常比整屏追随指针更有深度。装饰反馈不能让实际点击目标不断逃离用户。

**失去质感的征兆：** 每个元素都追着指针；反馈与对象无关；特效盖住文字或系统光标；只有悬停才能获取核心信息。

磁吸、位移和可变字体参数未必需要 WebGL；连续液体或网格形变则属于另一档实现成本。

## 模式六：动态排版与环境生命感

动态排版负责注意力：分行显露、错峰进入、尺度变化、图文衔接。环境运动负责气氛：水波、漂浮、光线变化、少量粒子。两者可以共存，但不能共享同样强的存在感。

共同的运动语言包括时长、加减速、停顿、错峰、阻尼和幅度。把它们作为可以调节和比较的设计参数，不把一组数字固化成全站“高级感公式”。短促、轻盈、沉稳、迟缓是不同性格；弹簧也不是所有动作的默认曲线。

**失去质感的征兆：** 每句话逐字弹跳；阅读中的正文持续漂移；环境循环不停抢焦点；所有动作都使用同一套夸张回弹。

参考 Dennis 的微交互与排版节奏。复现时首先验证真实中文内容，而不是只展示短英文标题。

## 一份足够具体的局部设计说明

下面是“精选作品画廊”的示例提案，不代表本站已经采用：

> **目标感觉：** 可以拨动的展品，轻盈但有稳定落点。
>
> **视觉结构：** 当前作品最清楚，其余作品保留前后层次。
>
> **输入映射：** 拖动控制位置，速度控制有限倾斜。
>
> **运动规则：** 直接响应，松手衰减，停止后保持可读。
>
> **状态衔接：** 选中作品扩展为内容入口。
>
> **实现候选：** DOM 位移、CSS 3D、带形变的 WebGL，按所需能力比较。
>
> **需要验证：** 拖拽与点击区分、触屏/键盘路径、可见作品数、纹理与图片负载。

说明应让另一个设计者能复现核心关系，同时留出构图与细节的发挥空间；不需要为每个按钮制作一套同样长的文档。
