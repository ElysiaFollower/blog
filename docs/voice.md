# 站点文案

## 读者

博客主要面向因为研究、代码或作品来到这里的人。默认读者能够理解技术，
也愿意认识作者本人；不使用幼龄化语气，不把页面写成产品广告。

## 三种语气

### 展示页

首页、About、相册和友链可以有文气，但一句话只承担一个意象。文字应该表达
内容与情绪，不解释一个模块为什么有资格存在。

例如：

- “光影停在画面里，旧日的心绪也有了归处。”
- “我希望 AI 不只听见一句话，也能听懂说话的人。”

### 个人表达

说到兴趣和创作时，可以像 GitHub Profile 一样轻松一点。俏皮来自具体的性格，
而不是堆叠网络用语：

- “主线之外，还有许多兔子洞。”
- “研究之外，也认真玩耍。”

颜文字只偶尔出现在问候或联系入口，不作为每段文字的标点。

### 功能文案

文章目录、搜索、排序、错误和加载状态直接说明发生了什么、下一步能做什么。
不追求文学效果，也不用“赋能”“探索无限可能”一类营销语言。

## 避免

- 为相册、友链或 About 的存在辩护。
- 空泛地反复使用“记忆”“旅程”“脉络”“表达”等抽象词。
- 把简单动作写成教程式解说。
- 为了显得可爱而使用低龄词汇。
- 为了显得正式而写成无主语的项目报告。
- 每句话都押同一种节奏，或机械地凑成三项并列。

更新公开文案时，应同时检查它在页面中的断行与上下文；单独读起来漂亮，
不代表放回版面后仍然合适。
