# 交互式文章

交互模块不是装饰，而是一种解释工具。它适合回答纯文字难以表达的问题，例如：

- 改变参数后，模型内部状态如何变化？
- 前向传播与反向传播分别经过了哪些节点？
- 一个算法逐步执行时，当前不变量是什么？
- 图像、音频或几何对象在不同表示之间如何转换？

所有文章都使用 `index.mdx`，但默认仍然只写普通 Markdown。只有当读者的操作能够帮助验证直觉、比较状态或理解过程时，才插入组件。

## 三档内容能力

### 1. 叙述内容

直接写 Markdown，包含文字、公式、代码、图片和表格。这是默认形态，构建结果不需要文章专属 JavaScript。

### 2. 富媒体解释

在正文中插入视频、分步图示或已有的通用组件。媒体必须有标题或上下文；`Video` 提供原生播放控件、`playsinline` 和可选封面，不自动播放带声音的内容：

```mdx
<Video
  src="/media/forward-pass.webm"
  title="前向传播过程"
  caption="固定权重后逐层展示节点激活。"
/>
```

### 3. 交互解释器

调用交互组件，展示网络层、张量、损失曲线、算法状态或可调参数，并在浏览器中响应读者操作。当前提供的 `BackpropExplorer` 会根据 XOR preset 真实计算前向值、交叉熵和权重梯度：

```mdx
<Stage>
  下面先固定权重，只观察损失如何沿计算图反向传播。

  <BackpropExplorer preset="xor" />
</Stage>
```

文章正文不负责组件初始化。可复用组件统一注册后，可以像短指令一样直接使用；组件通过 `preset` 等少量属性选择数据和初始状态。组件自身负责导入、校验和解释数据。

`Stage` 是独立的阅读布局作用域，不专属于交互组件。它可以包住一段关键正文与配图：普通文字保持正文行宽，媒体获得完整三栏宽度；滚动进入舞台时目录与外侧批注淡出，离开后恢复。舞台内部不设置边栏批注，补充信息使用正文、图注或 `Callout`。

通用解释器与 preset 集中存放：

```text
src/components/content/
├── BackpropExplorer.astro
└── interactive/
    └── backprop-presets.json
```

文章专属媒体与一次性数据仍放在文章目录中。内容 loader 只读取 `index.mdx`，不会把同目录的 JSON、TypeScript 或媒体误认为另一篇文章。

## 作者侧语法

作者需要记住的规则只有两条：

1. 文章始终写 `index.mdx`，没有第二种正文格式。
2. 默认按 Markdown 写；需要特殊表达时，直接插入 `<组件名 ... />`。

通用组件集中在 `src/components/content/registry.ts` 注册。注册后的组件会由文章路由统一提供，正文不再重复 `import`：

```mdx
<Callout title="关键观察">
  梯度在这个节点分成了两条路径。
</Callout>

<Stage>
  <BackpropExplorer preset="xor" />
</Stage>
```

组件名和属性保持少而稳定。复杂数据优先收敛为组件内的命名 `preset`，而不是让正文记住数据加载、路径解析和初始化代码。

一次性实验可以在 MDX 中显式导入组件或数据，但它属于开发接口，不作为日常写作方式。若同一种写法在两篇文章中出现，就应该考虑注册为通用组件，并把复杂数据收敛成命名 preset。

## 技术选择

从最小工具开始，按问题升级：

| 场景 | 首选 |
| --- | --- |
| 预先录制的过程 | 原生 `<video>` |
| 少量节点、曲线和可点击图形 | SVG |
| 大量二维元素或逐帧绘制 | Canvas |
| 三维空间与相机交互 | Three.js / WebGL |
| 简单状态与控件 | Astro 组件中的原生 TypeScript |
| 状态关系明显复杂 | 再评估 Preact 等 UI 框架 |
| 已有的独立 HTML Demo | 最后才考虑受限的 `iframe` |

Astro 组件中的 `<script>` 已经支持 TypeScript、npm import 与打包，不需要为了一个滑块或 SVG 图安装 UI 框架。只有真实模块出现复杂状态同步时，才增加框架，并将其作为独立 client island 加载。

昂贵计算优先在构建期完成，将必要的张量快照或轨迹保存为 JSON。浏览器只负责小规模计算和可视化。必须实时计算时，先评估 Web Worker；不要默认把完整模型权重和训练框架发送给读者。

## 交互契约

一个可以发布的解释器至少满足：

1. **无脚本仍可理解**：保留静态初始图、说明或数据摘要，而不是空白矩形。
2. **操作可以撤销**：复杂状态提供清楚的重置入口。
3. **输入方式完整**：鼠标、触屏和键盘都能完成核心操作，信息不只依赖颜色。
4. **动画可以停止**：离开视口时暂停逐帧计算；尊重 `prefers-reduced-motion`。
5. **尺寸稳定**：初始化前后不推动正文跳动，小屏不产生页面级横向滚动。
6. **解释先于控件**：正文说明读者要观察什么，组件不承担整段理论叙述。
7. **状态可复现**：随机演示使用固定种子；值得分享的状态再考虑写入 URL。

## 加载与索引

- 轻量原生脚本随组件打包，并在页面中隔离作用域。
- 图表库、模型或大数据应在组件接近视口时动态加载。
- 视频使用 `preload="metadata"` 或 `preload="none"`，避免打开文章就下载完整文件。
- 全文索引保留组件标题、说明与图注；滑块标签、坐标刻度等重复界面文本使用 `data-pagefind-ignore` 排除。
- 交互模块不能成为文章唯一的信息来源。搜索结果、RSS、打印与无障碍工具都需要一份可读的文字上下文。

## 当前边界

GitHub Pages 可以运行浏览器端交互，但不提供文章专属后端。因此下列能力需要单独评估：

- 大模型或大规模神经网络的在线推理
- 需要私密密钥的 API
- 保存读者状态、多人协作或服务端计算

这不妨碍大多数教学型模块。神经网络逐层观察、反向传播、优化轨迹、信号变换与图形学演示通常可以使用小规模实时计算或预计算快照完成。

## 已有实现

- `Video`：原生视频，默认 `preload="metadata"`，支持封面和图注。
- `Stage`：跨越阅读三栏的通用舞台范围，负责滚动转场和边栏退场。
- `BackpropExplorer`：2–2–1 XOR 网络，支持四组样本、四个观察阶段和实时梯度计算。
- [`src/content/posts/notes/ai/neural-networks/backpropagation/index.mdx`](../src/content/posts/notes/ai/neural-networks/backpropagation/index.mdx)：完整写作样例。

新增通用组件后，在 `src/components/content/registry.ts` 注册一次即可供所有文章使用。
