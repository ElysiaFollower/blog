### 1. 核心问题一：缺少真正的增量批次懒加载（Incremental Batch Lazy Loading）
- **当前现状**：SSR/页面初始化时直接将全量图片节点一次性注入 DOM，首屏加载负担重，未实现优雅的流式增量渲染。
- **目标形态**：参考即梦 AI 绘图展厅或 Pinterest 的无限瀑布流体验。当用户向下滚动接近底部时，通过 `IntersectionObserver` 自动触发下一批次（Batch）图片的增量加载与追加渲染。
- **占位与比例适配**：利用图片预置的 `width` / `height` 属性（或 `aspect-ratio`）提前完成 DOM 容器的精确占位，彻底消除加载抖动（CLS）。同时优化横竖图的尺寸适配策略，防止竖向大图过分挤占空间、横图过小的问题，使展示尺寸与图片原生分辨率更加协调。

### 2. 核心问题二：序号与排版编排方向倒置（Column-First Order Misalignment）
- **当前现状**：目前依赖原生 CSS `columns` 布局，渲染流动方向被限制为“先垂直列后水平”——即第 1 列从上倒下排满后才排第 2 列。这导致编号（01, 02, 03...）纵向垂直交错，且增量加载时优先填满特定列，严重违背了用户从左到右、从上到下的自然阅读直觉。
- **目标形态**：重构为按批次（Batch-First）横向分布的瀑布流编排逻辑。序号与加载顺序严格与用户视口扫视方向一致，确保增量加载时新图片平滑、均匀地补充到各列底部。
